# Plugin uploads through VS Code

Minecraft runs as `mc-<instance>`, while Remote SSH/VS Code uploads run as the local operator account. An uploaded or atomically replaced JAR can belong to `ubuntu` with mode 0600. A directory's default ACL cannot guarantee access after an editor explicitly sets that mode: the ACL mask can remove named users' effective read permission. The backup read helper deliberately ignores files owned by unrelated accounts and grants only paired Host access, so it cannot solve Minecraft's permission failure.

The optional `plexonpanel-plugin-read@.service` is a root-owned, instance-scoped guard for direct plugin uploads by the explicitly trusted `ubuntu` account. It repairs only regular, single-link, same-filesystem, top-level `plugins/*.jar` files owned by that uploader or the selected Minecraft account. Directory and JAR descriptors are pinned; symlinks, foreign owners, hardlinks and cross-filesystem entries are rejected/skipped. Only Minecraft read and paired Host backup read are added. The uploader retains ownership and editing access; Host never gets write access. Previously ineffective rights of other principals remain ineffective.

The guard does not walk plugin directories or grant access to pairing, identity, audit, configuration, worlds or credentials. Existing `plexonpanel-backup-read@` remains responsible for Minecraft-owned backup contents. Minecraft-owned JARs missing their owner's read bit receive that read bit only. The guard performs an initial scan before reporting startup and rechecks once per second, repairing new restrictive uploads, chmod and atomic replacements.

Use the verified helper and unit from the approved Core commit. Back up the existing root-owned helper outside the server trees. Install the helper root:root 0755 under `/usr/local/lib/plexonpanel/instance-read-authority.py` and the new unit root:root 0644 under `/etc/systemd/system/plexonpanel-plugin-read@.service`. Verify checksums and systemd parsing, run `systemctl daemon-reload`, then `systemctl enable --now plexonpanel-plugin-read@tonimsmp.service`. This starts only the new guard; no Minecraft or Host restart is required. Provision another instance only when its operator-upload policy is explicitly intended.

Verify a new 0600 operator-owned test JAR is readable as `mc-tonimsmp` and `pph-tonimsmp`, remains non-writable to Host, and remains inaccessible to other instance accounts. Remove the disposable test JAR after checking. Replacing the helper file does not change already running read helpers; the new guard process uses the new implementation independently.

A JAR rejected during Paper startup does not load retroactively when its permissions are repaired. Loading it requires a planned Minecraft restart after players are warned. Do not use plugin hot-reload tools as a substitute. Permission repair itself is safe while Minecraft is running.

For rollback, disable/stop only the new plugin-read guard and remove its enablement. Previously added read ACLs remain; restore saved JAR ACL metadata if those reads must be removed. Do not replace the shared helper while a required existing read helper is being restarted; preserve the verified original helper for coordinated rollback.
