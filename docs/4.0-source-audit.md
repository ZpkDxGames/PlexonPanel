# PlexonPanel 4.0 source audit

Audit baseline: backend `main` at `40a1c94892f83bdd3c7e82ec89196fcae8ced371`, with the reviewed
changes from PRs #75 and #76 carried by exact commits. Dashboard baseline is recorded in the
coordinated Dashboard repository audit.

## Reviewed surfaces

- Gradle modules, Java 25 toolchains, Paper 26.2 API, plugin descriptor, packaging and CI.
- Protocol envelopes, canonical signing, replay/timestamp gates, pairing, immutable grants,
  scope/action maps, bounded queues, audit and redaction.
- Paper lifecycle, reload/shutdown, Bukkit thread ownership, telemetry cadence, snapshots,
  presence/history, command policy and PlexonCore isolation.
- Host non-root startup, exact systemd unit binding, journald source and cursor pagination,
  RCON loopback channel, process argument construction, filesystem boundaries and persistent state.
- Full-backup preflight, traversal/exclusions, symlink policy, ZIP/hash verification, rclone
  promotion, remote hash verification, retry, local cleanup, durable job state and restart path.
- Examples, migration, release workflow, manifest/checksum generation, documentation and rollback.

## Findings and disposition

| Severity | Finding | 4.0 disposition |
| --- | --- | --- |
| Release blocker | Paper and Host configs lacked an explicit release schema/migration boundary. | Added backed-up atomic schema-4 migrations; root-owned Host policy uses a local stopped-service operation and future schemas fail closed. |
| Release blocker | Release metadata and CI assertions were pinned to historical commits/runs. | Replaced by the 4.0 release contract and gate evidence consumed at packaging time. |
| High | Publishing could imply security/runtime PASS without current 4.0 evidence. | Stable workflow requires explicit 4.0 gate evidence; source CI cannot promote itself. |
| Medium | 3.5.1 progress/history work was split across stacked PRs. | Carried by exact commits, reviewed as additive Protocol 3 behavior, then versioned as 4.0. |
| High | The 3.5 main line removed the Paper fallback required by the 4.0 directive. | Restored an explicitly configured, bounded and redacted live-only fallback with signed relay authority transitions; Host remains preferred and owns retained history. |
| Medium | Active examples named the 3.5.1 Host JAR. | Active examples now name `plexonpanel-host-4.0.0.jar`. |
| Accepted limitation | Network-reachable restore code exists for compatibility but Host capability is forced off. | Remains explicitly unsupported; local operator restore is documented. |

## Verification status

The pre-existing latest GitHub Java 25 x64/ARM64 runs for the carried PR heads passed. The local
workspace cannot download the Gradle 9.7 distribution and only has Java 17, so it is not counted
as backend execution evidence. The 4.0 branch must pass the repository Java 25 GitHub Actions
matrix before merge. Runtime, security, backup, console, history, and recovery certification remain
`NOT_EXECUTED` until their live gates are run against the exact release artifacts.
