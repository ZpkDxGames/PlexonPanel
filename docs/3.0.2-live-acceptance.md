# PlexonPanel 3.0.2 live acceptance

This checklist is the final release gate for the 3.0.2 reliability candidate. Do not mark the release complete merely because CI is green.

## Preconditions

- Deploy the matching 3.0.2 relay and Dashboard first.
- Keep protocol v3.
- Preserve the existing Paper identity, Host identity, and `plugins/PlexonPanel/access/devices.json`.
- Do not re-pair the existing Owner device unless a future release actually introduces a new immutable scope.
- Stop Minecraft before replacing the Paper JAR.

## 1. Install Paper and Host 3.0.2

With Minecraft stopped, replace the Paper plugin JAR with `PlexonPanel-3.0.2.jar` while leaving the plugin data directory intact.

Replace the Host companion with:

```text
/opt/plexonpanel-host/plexonpanel-host-3.0.2.jar
```

Ensure the Host unit points to the 3.0.2 filename and includes:

```ini
[Service]
SuccessExitStatus=143
Restart=on-failure
RestartSec=5
```

Then apply the unit change:

```bash
sudo systemctl daemon-reload
sudo systemctl restart plexonpanel-host
sudo systemctl status plexonpanel-host --no-pager
```

## 2. Verify Host-only control-plane state

Before starting Minecraft:

```bash
sudo systemctl is-active plexonpanel-host
sudo systemctl is-active plexoncraft || true
sudo journalctl -u plexonpanel-host -n 80 --no-pager
```

Expected Dashboard state:

```text
Host: Connected
Paper: Offline
Service: Stopped
```

The Dashboard must remain usable and `server.start` must be available from Host alone.

## 3. Start Minecraft from the Dashboard

Use the Dashboard Start action. During startup, observe:

```bash
sudo journalctl -u plexonpanel-host -f
```

and, separately:

```bash
sudo journalctl -u plexoncraft -f
```

Expected transition:

```text
Host: Connected
Service: Starting
Paper: Connecting
```

followed by:

```text
Host: Connected
Paper: Connected
Service: Running
```

After Paper connects, run in the Minecraft console:

```text
ppanel diagnostics
```

Confirm relay authentication is true, no persistent BACKOFF remains, and the latest protocol rejection field is empty or historical rather than continuously changing.

## 4. Stop Minecraft from the Dashboard

Use the Dashboard Stop action.

Expected transition:

```text
Paper: Disconnecting
Host: Connected
Service: Stopping
```

followed by:

```text
Paper: Offline
Host: Connected
Service: Stopped
```

Confirm Host did not enter an authenticate → `access.sync` → 4008 reconnect loop:

```bash
sudo journalctl -u plexonpanel-host --since "10 minutes ago" --no-pager \
  | grep -E "Authenticated with relay|Relay closed connection|4008|access" || true
```

## 5. Twenty-cycle lifecycle stress test

Perform at least 20 consecutive Dashboard Stop → Start cycles. For each cycle verify:

- Host remains connected while Paper is offline.
- Start remains available from Host alone.
- Paper authenticates again after the service starts.
- No generic 4008 reconnect loop appears.
- Dashboard telemetry resumes without a browser reload.
- No stale state persists beyond the configured freshness threshold.

After the stress test inspect both services:

```bash
sudo systemctl status plexonpanel-host plexoncraft --no-pager
sudo journalctl -u plexonpanel-host --since "1 hour ago" --no-pager
sudo journalctl -u plexoncraft --since "1 hour ago" --no-pager
```

## 6. Paper reload recovery

From the Minecraft console:

```text
ppanel reload
ppanel diagnostics
```

Expected:

- Paper reconnects.
- Host remains connected.
- Dashboard stays live.
- Existing access grants remain unchanged.

## 7. Host restart recovery

```bash
sudo systemctl restart plexonpanel-host
sudo systemctl status plexonpanel-host --no-pager
sudo journalctl -u plexonpanel-host -n 100 --no-pager
```

Expected:

- Paper remains connected.
- Host reconnects automatically.
- Paper does not receive a 4008 because a Host peer delivery failed.
- Lifecycle controls return automatically.

## 8. Intentional Host stop semantics

```bash
sudo systemctl stop plexonpanel-host
sudo systemctl status plexonpanel-host --no-pager
```

Expected result is a successful stopped state such as `inactive (dead)`, not `failed (Result: exit-code)`.

Restart it afterwards:

```bash
sudo systemctl start plexonpanel-host
```

## 9. Browser close/reopen

Close every Dashboard tab, wait long enough for stale browser sockets to be cleaned up, then reopen the Dashboard.

Expected:

- Paper and Host stay connected while the browser is closed.
- Reopening does not cause agent protocol churn.
- Fresh state loads without re-pairing.

## 10. Temporary relay/network interruption

Simulate a brief relay/network loss using the deployment environment's normal safe test procedure.

Expected:

- Paper and Host enter reconnect/backoff.
- Both recover automatically once connectivity returns.
- No maintenance scheduler dies permanently.
- No identity rotation or device re-pair is required.

## Release decision

3.0.2 is ready to leave draft only after all automated checks pass and every live item above has evidence. Keep the access registry and identities intact throughout the exercise.
