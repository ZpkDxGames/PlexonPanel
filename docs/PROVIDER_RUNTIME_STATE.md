# Private provider credential state

Rclone's configuration contains credentials and token providers require writable configuration for refresh. Its documented save procedure uses temporary files and rename in the configuration's parent directory. A read-only `/etc` seed is therefore insufficient for long-running OAuth operation. Primary documentation: <https://github.com/rclone/rclone/blob/master/docs/content/docs.md>.

Schema 5 retains the immutable per-instance seed `/etc/plexonpanel/instances/<key>/rclone.conf`, root-owned and readable only by the paired Host group. After acquiring the exclusive fleet identity lease, the Host seeds `/var/lib/plexonpanel/instances/<key>/provider/rclone.conf` once. The provider directory is Host-owned mode 0700; the writable config and private source marker are mode 0600. Backup, preflight, upload/retry and maintenance providers receive this derived path. The public/configured remote namespace remains bound to the same server UUID; browser data cannot select a config file.

Ordinary restart preserves refreshed credentials, including an atomic provider config replacement. It never copies the original seed over existing refreshed state. Two instances have distinct private provider directories. Symlink redirects, foreign/public files and a changed immutable seed are rejected. A crash between first config publication and marker publication can retry only when the existing config still exactly equals its seed; otherwise operator recovery is required.

The source fingerprint is stored only inside private Host state. It is not telemetry, a manifest field, a log field or a public credential checksum. Neither seed contents, refreshed credentials nor fingerprint values are printed by the helper or its failure boundary.

An intentional provider rotation requires stopping the affected Host, privately preserving its entire provider directory for rollback, validating the replacement seed and explicitly reseeding the isolated provider state. Do not delete/reseed while the Host runs, silently overwrite refreshed state or copy another server's provider directory. The local administrator can review `--plan-provider-reseed <key>` and explicitly apply `--reseed-provider <key>`. Apply requires an inactive/failed paired Host service and an available existing fleet identity lease. It atomically preserves the entire provider directory under a private `provider.pre-reseed-<UUID>` path without deleting any credentials. After validating node configuration, the next normal paired Host startup seeds the replacement config as its own account. The operation is absent from network action routing. Actual provider authentication/refresh/upload certification remains NOT_EXECUTED.

Local filesystem tests execute distinct-instance seeding, mode checks, atomic credential refresh, restart preservation, interrupted seed retry, source rotation denial and missing/symlink/unsafe state rejection. These source checks do not prove an actual remote upload or OAuth refresh on the VPS.
