# Coordinated instance service deployment

The `host-agent/examples/fleet/` templates implement the finalized canonical CLI/config, exact polkit service authority, stable node lock and bounded shutdown contracts. They are supplied for the coordinated 5.0 deployment. They are not installed or enabled by this source change. Do not deploy them alongside the retained VPS relay 3.5 or substitute an intermediate Host/Paper artifact. Stable publishing remains withheld until migration, runtime and security gates pass.

## Boundaries and resource budget

`minecraft@<key>.service` runs `mc-<key>` in its exact server root; only that tree is writable. Its JVM arguments are in `server/jvm.args`; the supplied starting heap is 1–6 GiB, with a 7 GiB soft and 8 GiB hard cgroup limit. `plexonpanel-host@<key>.service` runs `pph-<key>`, with a 256 MiB Java heap and 512 MiB cgroup limit, writable private state/backups and the existing shared lock. Unix permissions prevent creating or replacing lock inodes. Host cannot write the server or its root-controlled configuration.

Two instances have a maximum 17 GiB combined Minecraft/Host cgroup allocation, within the reported 23 GiB VPS RAM. Existing services, native memory, filesystem cache and backup workloads still require actual capacity validation. These defaults are an initial budget, not a measured runtime certification. Tune instance drop-ins and `jvm.args` together before adding more servers. Root must own launchers, helper scripts, service units and polkit rules; Minecraft must not belong to Host or backup groups. Host supplementary membership is limited to `plexonpanel-backup`, never global `systemd-journal`, `adm` or other instances' groups.

Both JVM services receive SIGTERM. Paper has 90 seconds for Minecraft's shutdown/save hook; Host has 75 seconds, exceeding its 45-second worker-drain budget. SIGKILL after timeout is a failed graceful shutdown requiring recovery investigation. Actual world-save interruption/restart tests remain required.

## Read and journal authority

Install the root-owned `instance-read-authority.py` under `/usr/local/lib/plexonpanel/`. The backup helper scans only the registered canonical server tree, repairing a named paired-Host read/traverse ACL. It uses pinned directory/file descriptors, never follows symlinks, rejects foreign owners, cross-filesystem entries and multiply linked regular files, and excludes Paper identity/audit and temporary Spark state. It adds no Host write permission and preserves other principals' previously effective permissions. Mode-0600 creations, chmod and atomic replacement are repaired on the next two-second scan. Backup preflight remains the fail-closed authority if a file is still unreadable; unreadable files must never be silently omitted.

Minecraft logs use the exact `plexonpanel-<key>` journal namespace. The journal helper can modify only `/var/log/journal/<machineId>.plexonpanel-<key>` inside its systemd filesystem sandbox. It grants read access to root-owned `.journal` files and traversal in that namespace; no global journal membership is required. Pre-create the namespace with the root-only `prepare-journal <key>` command before starting this helper. Omitting that step fails the unit's writable-path setup safely; a missing path is not silently ignored. Live/history readers additionally pin the exact Minecraft unit.

The `prepare-lock` command creates the node's root:`plexonpanel-backup` 0660 lock once per boot below root-owned 0755 `/run/plexonpanel/locks`. An existing inode is validated and never truncated, replaced, removed or repaired in place. Do not restart with an invalid shared lock or replace it while any Host is alive.
