## Limited acceptance and rollback

A separately approved Oracle preflight should collect an allowlist of fields for Docker engine and image IDs, Java and relay versions, container ID and start time, effective container logging/stdin settings, port bindings, transport/LAN policy, and relay/proxy routing. Obtain local checksums for the incumbent relay release and candidate, plus the exact systemd executable and release pointer. Keep credential values, private network details, and raw container configuration in the operator's private change record. Confirm the expected three Paper and three Host connections, record the three room identifiers and take a read-only view through an authorized existing browser device. If an environment detail cannot be replicated, ask the operator to explicitly accept the documented difference and agree to a passive control-plane smoke within the change window. If provenance, authorization, or a safe rollback target remains unresolved, retain HOLD.

Before an approved cutover, record the immutable prior relay package path and checksum, the unit and drop-ins, protected env/config files, and an online SQLite backup of each database. For each existing database, make the backup as the service owner or authorized operator to a new private directory with `umask 077` using SQLite's `.backup` through one connection. Run `PRAGMA integrity_check;` on the resulting snapshot and require `ok`, then hash the files. Keep the SQLite database path, token secret, relay signing keys, and proxy entrypoint stable. Treat use of an older database snapshot as a separate recovery decision because it can roll back device revocations.

In an approved window, use only the named read-only Bedrock Host and broker services and the pinned relay. Verify the six legacy connections, three stable room IDs, scoped Paper reads and denial of an out-of-scope request, one authorized Bedrock read-only session, bounded fresh redacted logs, and denial of Bedrock remote actions. Require the existing Bedrock container ID and launch timestamp to stay fixed. Loss of a legacy room outside the agreed reconnection budget, invalidation of a valid scoped session, a revoked session accepted, exposed sensitive log data, unexpected Docker access, or a game launch change triggers rollback.
